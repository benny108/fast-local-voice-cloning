# ZipVoice-Distill 中文故事旁白：详细技术方案

核验时间：2026-10-07。本文对应当前试听确认的 **A 参考、4 步、原生 1.05 倍速**。
本文报告本地实测，不把上游宣传、GPU 理论值或其他机器成绩当成本机结果。

## 1. 目标与边界

### 1.1 目标

- 为中文知识动画和故事旁白生成比默认快速念稿更从容的声音。
- 尽量在普通 Apple Silicon 笔记本上快速生成一分钟左右的语音。
- 不调用收费云 API，也不把参考声音上传到外部服务。
- 保留可核验的设置、耗时及音频质量检查结果。
- 将工程参数公开，参考录音和声音特征继续放在本地。

### 1.2 不承诺的内容

- 不承诺“完全真人”“完美复刻”或任意情绪指令都有效。
- 不承诺每句仅靠文本就能精确停顿 0.5 秒。
- 不把一次试听认可转换成客观相似度分数。
- 不因为模型代码开源，就推断第三方声音可自由商用。
- 不把本机测试写成跨硬件、跨平台的性能保证。

## 2. 总体架构

```text
原创口播稿 ──────────────────────────────────────┐
                                               │
本地参考 WAV + 准确参考逐字稿                    │
        ↓                                      │
参考特征提取 / 文本归一化与音素化                │
        ↓                                      ↓
     ZipVoice-Distill（主模型运行在 MPS，4 步，speed=1.05）
        ↓ 预测声学特征
     Vocos（CPU 解码）
        ↓ 钳位前峰值保护
     模型原生长文本分块拼接与边缘静音处理
        ↓
     24 kHz 单声道 WAV
        ↓
     响度归一化 / MP3 编码
        ↓
     完整解码 + 本地转录检查 + 人工试听
        ↓
     视频时间轴、字幕、音乐与事件音效
```

“一次提交全文”不等于内部绝不分块。当前上游会依标点把长文本分成较长的块，再批处理和交叉淡化拼接。
我们不再手工把全文拆成 19 个独立推理调用。

主模型和 Vocos 分开运行：在本次 PyTorch 2.5.1 环境中，CPU 声码器避开了 MPS 上遇到的 ISTFT 相关兼容问题。
这不是宣称所有 PyTorch 版本都不能在 MPS 上运行 Vocos；将来切换版本后仍需单独测试。

## 3. 已确认的参数

参数文件：[配置模板](../profiles/a-1.05-4steps.example.json)。

| 参数 | 当前值 | 含义与注意事项 |
|---|---:|---|
| 模型 | `zipvoice_distill` | 蒸馏版，主模型约 123M 参数 |
| `steps` | `4` | 采样计算步数；不是朗读倍速 |
| `speed` | `1.05` | 模型原生语速控制；不使用后期音频拉伸 |
| `guidance_scale` | `3.0` | 本次使用的条件引导设置，不是“音色浓度”滑块 |
| `seed` | `666` | 降低随机差异，不能保证跨环境逐样本一致 |
| `threads` | `4` | PyTorch CPU 线程设置，不是 GPU 核心数量 |
| `device` | `mps` | Apple Silicon 主模型推理设备 |
| `vocoder_device` | `cpu` | Vocos 解码设备 |
| `max_duration` | `30.0` | 上游批处理预算参数，不是限制成品最多 30 秒 |
| 峰值保护 | `0.85` | Vocos 输出在上游硬钳位前做必要的整体衰减 |
| 输出采样率 | `24000` | 原模型及 Vocos 对应 24 kHz |
| 量化 | 未使用 | 本次不是 ONNX INT8 或 GGUF 测试 |
| 后期加静音 | 无 | 当前认可版本仅使用模型自身生成的停顿 |

在此前试听中，1.25 倍速度显得更赶；使用者认可 1.05 倍版本。
“认可 1.05 倍”与“模型完美解决了停顿”不是同一结论。

### 4.2 准备环境

安装指引依据固定上游依赖和本机已装版本整理。此次验证使用已有环境，未另建空环境重做下载安装；新机器仍需验证依赖兼容性。

macOS 不照搬 CUDA 专用 k2 安装命令。k2 对本方案的推理不是必须项。

本地封装通过 `--repo-root` 加载上游代码，不依赖未提供的 `pip install -e` 打包入口。

## 5. 参考录音与“音色参数”

### 5.1 不是训练专属音色

此次没有微调，没有 LoRA，没有导出一份 A 音色模型。
每次推理从参考 WAV 中提取特征，并结合参考逐字稿进行零样本克隆。

因此：

- 上传配置可以复现计算设置。
- 上传通用模型链接可以获取基础模型。
- 只有同样的合法参考音频、逐字稿、文本、权重和环境，才有条件复现相近的声音。
- `seed` 或 `guidance_scale` 不是独立的声音身份。

### 5.2 准备自己的参考

1. 录制干净单人语音，尽量无背景音乐、混响、其他人说话。
2. 为速度测试可先选择约 2–3 秒清晰片段；此次 A 参考是 2.1 秒。
3. `reference.txt` 必须准确对应这段录音，不能放整篇配音稿或导演指令。
4. 太短、带混音的片段可能不足以表现说话习惯；比较不同片段时固定正文与参数。
5. 如需更长参考，先单独 A/B 试听并测量成本，而不是默认越长越好。

上游推荐单人生成使用较短参考以提升速度；它并不保证任意两秒片段都有最佳克隆效果。
声码器和推理路径使用 24 kHz，输入由上游加载流程处理；不要把简单升采样说成音质修复。

### 5.3 本次不公开的素材

当前 A 来自第三方视频，未确认声音的公开再分发授权。公开仓库不包含其 WAV、逐字稿、试听结果或参考特征。
完整边界见 [公开范围](PUBLICATION_SCOPE.md)。

## 6. 文本、停顿与念稿感

### 6.1 三个不同的问题

- **内容问题**：是否从具体事情推进，有矛盾、过程和结果。
- **朗读问题**：语速、重音、断句、句尾是否像人说话。
- **剪辑问题**：是否给画面变化、重要数字和观众理解留出时间。

模型、文案和后期各解决一部分问题，不要把换音色当成全部修复。

### 6.2 当前版本的文本控制事实

本方案核对了固定版本的 `EmiliaTokenizer` 和实际词表：

| 输入方式 | 实际处理 | 能否精确指定时长 |
|---|---|---|
| `。`、`，`、`；`、`：`、`？` | 转成对应标点 token | 不能保证 |
| 换行 | 当前分词过程中被忽略 | 不能 |
| `……` 或 `...` | 归一化到省略号，但省略号是 OOV，被跳过 | 不能 |
| 写“每句停半秒” | 没有对应的通用导演指令接口 | 不能当可靠控制 |
| `[停顿0.5秒]` | 不是此词表中的有效停顿标签 | 不能 |
| `prompt_text` | 参考录音逐字稿 | 不是表演提示词 |

不要通过堆省略号、空行或不支持的标签制造“已经控制住停顿”的错觉。

### 6.3 本次试过的三种方式

**方式 A：全文标点调整。** 不换正文，不额外插静音。原稿 52.285 秒，调整稿 52.456 秒。
多数句间空隙变化很小，未做到每句稳定停 0.5 秒。

**方式 B：19 句分别生成。** 每句生成后接入 0.5 秒静音，18 个连接检查为零样本。
停顿确定，但累计生成约 22.6 秒，不含加载，并可能削弱连续起腔的感觉。

**方式 C：全文原生 1.05 倍速。** 不再拆成 19 次生成，也不后期拉慢；输出 62.414 秒。
使用者认可这版效果，因此把它作为当前旁白基线。

### 6.4 后续推荐工作流

```text
先把稿子改成具体故事
    → 全文 1.05 倍生成并试听
    → 只标记确实连读、转折过急或需要配合画面的局部
    → 优先在已有自然静音边界延长停顿
    → 无安全边界时重做局部，而非全片逐句重新生成
```

不在字音或擦音中间硬插静音。必要时采用本地字词对齐与静音检测定位；这是后处理，不是假装模型理解了情绪指令。
补停顿后重新检查完整解码、接缝、字幕与画面时间轴。

## 7. 运行与产物

### 7.1 先检查输入，不生成音频

```bash
python scripts/zipvoice_distill_local.py \
  --repo-root vendor/ZipVoice \
  --model-dir models/zipvoice/zipvoice_distill \
  --vocos-dir models/vocos \
  --reference private/reference.wav \
  --reference-text-file private/reference.txt \
  --text-file examples/story.txt \
  --output local-output/story-1.05.wav \
  --dry-run
```

`--dry-run` 检查配置、路径与文本，不加载模型，不创建输出目录或文件。

### 7.2 实际生成

去掉 `--dry-run` 即可。成功后输出：

```text
local-output/story-1.05.wav
local-output/story-1.05.json
```

JSON 包含实际时长、初始化和生成耗时、峰值、RMS、参数及上游指标。
它不记录参考录音、参考逐字稿、声纹特征或正文内容。已有 WAV 或 JSON 时脚本拒绝覆盖。

### 7.3 峰值保护

上游解码后有 `clamp(-1, 1)`。直接把超出范围的波形钳位，会产生失真。
封装在硬钳位之前，把确实过高的 Vocos 输出整体衰减到最大绝对值不超过 0.85。
不修改上游源码，不改变音调或播放速度；必要的解码增益会记入本地指标。

它不是高动态压缩、情绪增强、降噪或音色修复。完成合成后仍要进行统一响度处理。

### 7.4 音量与 MP3

试听使用 `-18 LUFS / -2 dBTP / LRA 11`，MP3 128 kbit/s。
如果已有 Easel 音频工具，复用其 `audio_ops.py normalize`；普通环境也可使用 FFmpeg：

```bash
ffmpeg -n -i local-output/story-1.05.wav \
  -af 'loudnorm=I=-18:TP=-2:LRA=11' \
  -b:a 128k local-output/story-1.05.mp3
```

`-n` 避免覆盖。用于正式视频时可另定混音标准；不要把“更响”误认成“更自然”。
转码后的采样率由编码与滤镜链决定；以探测结果为准，24 kHz 的原声不会因升采样恢复新细节。

## 8. 性能实测与比较方式

详见 [去敏测量数据](../evidence/benchmarks.json)。

| 测试 | 音频时长 | 初始化＋生成 | 单独生成阶段 | 备注 |
|---|---:|---:|---:|---|
| 当前稿、4 步、1.05 | 62.414 s | 11.045 s | 7.584 s | 当前认可基线 |
| 同稿、4 步、1.25 | 52.456 s | 9.016 s | 6.134 s | 速度参数对照 |
| 早期另一稿、4 步、1.25 | 54.578 s | 10.163 s | 6.364 s | 与下一行同文本 |
| 早期另一稿、8 步、1.25 | 54.558 s | 12.004 s | 8.968 s | 同参考、同语速 |

4 步相对同文本 8 步的生成阶段减少约 29%，包含加载的总耗时减少约 15%。
采样步数减半，不代表全部开销也减半。

不要把“19 句累计生成 22.6 秒（不含加载）”与“全文 11 秒（包含加载）”当完全相同口径。
它能说明多次调用有额外成本，不能据此声称模型本体性能突然变化。

RTF 可表示 `生成耗时 / 音频时长`，但音频中静音越多也会让这个比值显得更好。
比较时同时报告文本、语速、停顿处理、参考长度、冷/热启动、总耗时和单独推理耗时。

## 9. 质量检查

### 自动检查

- WAV 和最终 MP3 可以完整解码。
- 波形长度有效，样本均为有限值。
- 不是全静音，峰值不过载，无削波样本。
- 通过本地 ASR 检查明显漏句、错读和多余词。
- 需要补停顿时，检测实际静音而非只检查文字标签。

ASR 会把同音字识别成别的字，也可能自己漏字或加字。
转录相似度不能当成声音相似度、自然度或商业可用性的分数。

### 人工试听

- 有无漏字、重复、吞字、奇怪的句尾或杂音。
- 同一段声音是否稳定，有无起腔突变。
- 拒绝、疑问、揭晓是否有语义层次，而非只变慢。
- 重要信息之后是否有理解时间。
- 对比时使用同一正文、音量和设备，避免音量差异影响判断。

当前用户已经认可 1.05 倍试听，但还需对每条新稿做检查。

## 10. 视频制作集成

1. 将完整旁白 WAV 固定为本集的语音源。
2. 根据最终音频生成字幕和字词时间戳，不沿用旧版时间戳。
3. 让角色行为、信息揭晓和镜头转场跟随语义，而不是固定每隔几秒触发。
4. 如追加停顿，重新计算字幕、动画事件和最终时长。
5. 事件音效另轨管理；语音、人声授权、音乐和音效授权分别记录。
6. 音乐不能掩盖字音；静音补点不伪装成真人呼吸。

提高人味首先依靠故事、说话方式和合适的参考，再依靠少量后期。
不是先堆背景音乐，再把机械配音藏进去。

## 11. 常见故障

| 现象 | 检查与处理 |
|---|---|
| MPS 声码器报 ISTFT 相关错误 | 保持 Vocos 在 CPU，不盲目把整条链移到 MPS |
| 提示缺少 k2 | 当前推理可以使用回退路径；不因此宣称训练能力可用 |
| 音色不像 | 核对参考逐字稿，换干净参考，先排除音乐、混响、参考过短或内容错配 |
| 增加省略号却没停 | 此版本会跳过省略号，改用有效标点或局部后期 |
| 每句都像重新起头 | 避免整篇逐句独立合成；保持较长叙事上下文 |
| 有爆音或沙哑削波 | 检查钳位前峰值保护和最终解码，不只看播放器音量 |
| 新机器速度不同 | 分开测初始化、纯生成和转码，核对线程、设备和版本 |
| 模型文件没找到 | 使用显式模型路径，离线推理阶段不会自动补下载 |
| 重跑同名输出失败 | 这是防覆盖设计，使用新的输出文件名 |

## 12. 发布与许可

本次仅上传可公开的技术文档、原创封装、配置模板、原创示例文本和去敏测量数据。
第三方参考声音、试听媒体、声学特征、模型权重和本地环境都不上传。

上游 [ZipVoice 源码许可](https://github.com/k2-fsa/ZipVoice/blob/2f7326fbfe999a3ad179e3f1af82a424d4a62819/LICENSE) 为 Apache-2.0。
模型权重与 Vocos 的使用条件应分别查其模型卡；这不替代声音素材授权。
如果后续使用本人录音，也应明确决定是否公开，而不是因为配置上传就顺带上传 WAV。

## 13. 后续优化顺序

1. 保留当前 4 步、1.05 倍基线，先改善正文与参考录音。
2. 做局部停顿补点，避免全文逐句合成。
3. 批量任务可考虑模型常驻，减少重复初始化；当前脚本仍是单次进程，不虚报常驻性能。
4. 进一步评估 4/8 步、参考长度和其他推理后端，均使用同一正文与可比口径。
5. ONNX、GGUF、Metal 原生实现或其他模型需要新测试；本方案不把未测试方案当成已经加速成功。
