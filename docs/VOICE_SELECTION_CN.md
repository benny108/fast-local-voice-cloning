# 音色选择、克隆与复刻工作流

## 1. 先分清三件事

| 需求 | 本方案如何实现 |
|---|---|
| 换一个参考音色 | 更换本地参考 WAV 和准确逐字稿，保持其他参数固定 |
| 克隆自己的声音 | 录制本人参考，将其作为条件输入，零样本生成新正文 |
| 复刻同一次结果 | 保留参考、逐字稿、正文、参数、源码版本、权重和环境；不承诺跨机器逐样本一致 |

“音色选择”不是在 ZipVoice 中选择一个内置晓晓/云希 ID。模型没有附送这些声音。
本仓库提供参考录音目录约定与配置范例，使用者自行准备已授权的录音。

## 2. 本地音色目录

```text
private/
  voices/
    voice-a/
      reference.wav
      reference.txt
      authorization.txt
    voice-b/
      reference.wav
      reference.txt
      authorization.txt
```

`authorization.txt` 记录本人录制或获得授权的情况，不需要把个人信息放进公开仓库。
`private/` 整体被忽略。公开的 [目录模板](../profiles/voice-catalog.example.json) 只描述路径，不含音频、特征或声音权重。
当前推理脚本通过显式路径选择声音，不会自动解析目录模板，也没有在仓库中实现网页音色商城。

## 3. 录音与选段

- 使用正常说话方式，尽量避免刻意播音腔。
- 环境安静，麦克风距离稳定，不使用音乐或夸张混响。
- 为本方案的速度测试，先选约 2–3 秒的清晰完整短句。
- 参考逐字稿只写实际说出的内容，包含与录音一致的数字读法。
- 不把“开心一点”“磁性男声”“每句停半秒”写进参考逐字稿，冒充模型支持的指令。
- 录音太长、太短、含音乐或对白混杂，都会影响克隆和测试成本；没有越长越好的通用结论。

短参考有利于速度，但不足以描述所有情绪、句尾和长篇说话习惯。想更像自己，优先比较多个干净片段，而不是只调整速度。

## 4. 固定条件做 A/B 试听

选择同一段约 20–30 秒、包含叙述/疑问/转折的原创正文，对两份参考分别运行：

```bash
python scripts/zipvoice_distill_local.py \
  --repo-root vendor/ZipVoice \
  --model-dir models/zipvoice/zipvoice_distill \
  --vocos-dir models/vocos \
  --reference private/voices/voice-a/reference.wav \
  --reference-text-file private/voices/voice-a/reference.txt \
  --text-file examples/story.txt \
  --output local-output/voice-a.wav
```

将参考路径改为 `voice-b`，输出改为 `voice-b.wav`，其余设置保持不变。

当前配置为 **4 步、1.05 倍、seed 666**。
对照时统一最终响度；参考时长也尽量接近，并分别记录生成耗时。

| 项目 | A | B |
|---|---|---|
| 参考长度与干净程度 | | |
| 声音是否符合预期 | | |
| 问句、转折、句尾是否自然 | | |
| 有无漏字、重复、吞字 | | |
| 一分钟内音色是否稳定 | | |

记录“主观更喜欢 A”，不要伪造“相似度 99%”。本仓库没有客观声纹相似度评测程序。

## 5. 先选择音色，再调节奏

推荐顺序：

1. 固定正文与参数，选出更合适的参考。
2. 使用完整一分钟正文检查持续表现。
3. 先测试 1.05 倍，再根据内容密度比较 1.15/1.25；每次只改一个变量。
4. 对必要的理解点补少量停顿，不用音乐遮住语音问题。
5. 只有 4 步存在明显质量问题时，再与 8 步做同条件比较。

4 步是采样计算量；1.05 倍是原生语速。两者不是同一个“快慢”参数。

## 6. 怎样保存可复现方案

### 可以放进 GitHub 的部分

- 模型和声码器的原地址、版本及通用权重哈希。
- 原创正文、参数 JSON、运行脚本和环境约束。
- 去敏时长、耗时和质量检查结果。
- 不包含真实声学数据的目录模板。

### 应另行决定的声音资产

- 参考音频及逐字稿。
- 参考声学特征、speaker embedding 或特征缓存。
- 使用第三方参考生成的试听成品。

仅上传设置无法保证别人复刻同一音色。声音资产上传到私有仓库也属于向 GitHub 传输，本次不上传。

## 7. 关于“很快”

本机认可的完整旁白案例：62.414 秒音频，加载加生成约 11.045 秒。
这是一个样本，不是所有文章或硬件都能达到的 SLA。

首先避免全文逐句反复推理，其次再考虑模型常驻。当前脚本是单次进程封装，不包含常驻服务、前端或多用户管理。
这些可以作为后续工程，不混进已经完成的能力清单。
