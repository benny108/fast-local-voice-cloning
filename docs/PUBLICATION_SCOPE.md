# 什么可以上传，什么不能默认上传

## 可公开的交付内容

| 内容 | 本次处理 | 原因 |
|---|---|---|
| 技术方案、安装指引 | 上传 | 公开的工程说明 |
| 本地运行封装与配置测试 | 上传 | 不含录音、模型或凭证 |
| 4 步、1.05 倍、seed、线程数等 | 上传 | 通用推理参数，不是声音身份 |
| 原创虚构早餐店示例稿 | 上传 | 本方案原创教学文本 |
| 去敏测试用时、硬件、版本 | 上传 | 不含本地个人路径或声音素材 |
| 当前 A 参考 WAV | 不上传 | 来自第三方视频，未确认公开再分发授权 |
| 当前 A 参考逐字稿 | 不上传 | 没必要随公开包分发；使用者应提供自己的文本 |
| 用当前 A 生成的试听 MP3/WAV | 不上传 | 公开使用的声音授权尚未确认 |
| Speaker embedding、参考声学特征、特征缓存 | 不上传 | 属于可用于复现声音的敏感资源，不是普通参数 |
| ZipVoice/Vocos 权重 | 不上传 | 体积大，按上游模型卡从原地址获取 |
| 虚拟环境、下载缓存、绝对本地路径 | 不上传 | 不便携，可能暴露本地信息 |
| API Key、Token、Cookie、SSH Key | 不上传 | 不属于此方案，运行也不需要 |

## “音色参数”到底是什么

本方案没有进行音色训练，也没有导出一个独立的 A 音色权重。推理时使用：

```text
通用模型权重
    + 参考录音的声学特征
    + 参考录音逐字稿
    + 待合成正文
    + 速度 / 步数 / seed 等参数
    → 生成语音
```

`speed=1.05`、`steps=4` 或 `guidance_scale=3.0` 并不存储音色。
只拿到配置的人，可以复现运行方式，不能因此得到完全相同的声音。

参考特征不是“去掉 WAV 后就无隐私风险”的普通设置；也不把它放进 JSON、NumPy 或 Base64 文件绕开录音的公开边界。

## 想发布自己的声音

可以另行录制本人声音，确保逐字稿准确，然后决定只本地使用、私有仓库保存，或明确授权公开。
“私有仓库”仍会把资料上传到 GitHub，不等于继续只保存在本机。
Git LFS 只解决文件大小与版本管理，不解决素材授权或声音隐私。

第三方声音不是因为看起来像 TTS 就自动允许复用或公开克隆。
公开商用前，应分别检查上游模型许可、声音来源许可及使用场景。

## 提交前检查

```bash
git status --short
git diff --cached --stat
git diff --cached
```

只显式加入本方案的文档、代码、配置和示例文本，不执行针对整个个人工作区的 `git add .`。
`.gitignore` 不能隐藏已经被跟踪的文件，因此仍需审查暂存区。
